## `02 — What I do`

I come from **professional photography, lighting, retouching, e-commerce imaging and art direction**.

Software entered the picture because the same problems kept appearing in production: repetitive editing, fragile workflows, inconsistent image preparation, large media archives, disconnected tools and too much mechanical work.

Today I work at the intersection of **visual production and software**, building systems around the workflows I actually use.

## `05 — How I build`

My development workflow is increasingly **agent-assisted**, but the engineering principles stay deliberately conventional:

<div align="center">

`problem` → `issue` → `branch` → `implementation` → `tests` → `review` → `PR` → `CI` → `merge`

</div>

I care about **explicit requirements**, **small auditable changes**, **testing**, **documentation**, **security boundaries**, **observability** and **reversible operations**.

Agents can generate a lot of code. The interesting work is designing the system they should build — and knowing when they are wrong.
